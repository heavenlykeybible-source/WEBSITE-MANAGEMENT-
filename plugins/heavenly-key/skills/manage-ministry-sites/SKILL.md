name: manage-ministry-sites
description: Manage Heavenly Key websites and apps through its connected Control Room; inspect code, prepare complete multi-file changes, deliver uploads or GitHub releases, and explain real deployment and account permission status.
---
Use the connected Heavenly key tools first. List actual saved connections and destinations; resolve account labels instead of guessing IDs. Preserve each existing application's architecture, full functionality, ministry content, owner identity, passwords, databases, buckets, secrets and offline user data.

Inspect existing files and follow chunk pagination before replacing them. Use GitHub for a source project requiring compilation. For a static website, propose the complete built output or deliver a ZIP for Import and preview. For a Worker, deliver one bundled ES module with all required code and embedded assets; use the exact existing Worker and account. Never send page HTML as Worker JavaScript. An AI without tools can still produce the full downloadable package for the owner's Send work / deploy upload flow.

Prepare concrete changes, validate them, then submit one reviewable release. Group related files to reduce CI runs. Existing Worker updates must retain production bindings and secrets; never reset or seed a production database. Use preserved release versions for rollback and captured D1 recovery bookmarks for explicit data recovery.

Use offered read helpers such as list_workers, read_worker_source, find_project_files and read_file_chunk when the connection exposes them. Never claim an unavailable tool exists. Scope permissions to the requested work. For missing access, request the exact account through an offered permission tool and report the returned approval mechanism. Never approve an AI's own access or infer owner approval from a model response. ChatGPT's tool approval and Control Room's server grants are separate. Do not promise an inline ChatGPT popup unless that host integration actually returns one.

Use the normal Studio password sign-in or the authenticated Open Studio shortcut. Never request passwords, API keys or verification codes in chat. Ask the owner to set a new password in the private reset form when required. For TinyFish, check the installed provider configuration and available credits; distinguish the private Heavenly Key browser service from paid TinyFish API access. Do not start duplicate tasks after a timeout.

Report separately: source saved, proposal waiting, deployment succeeded, and live functionality verified. Use deployment logs and real tests; say which features remain unverified. Do not substitute a generic landing page for an app or claim media/live features work when no stream, recordings or provider configuration exists. Keep status updates concise.
